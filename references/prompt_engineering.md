# 提示词工程 — GLM Vision Skill

本文档记录 `assets/prompts.json` 的设计逻辑，供社区贡献者优化提示词时参考。
改提示词即可提 PR，不需要碰 Python 代码。

## 设计原则

### 1. 为什么 prompt 全中文

提示词是喂给 GLM-4.6V-Flash 这个 VLM 的，语言由 VLM 决定，与上游是 GLM-5.2 还是 DeepSeek 无关——上游 LLM 读的是脚本吐出的 JSON，不是 prompt。GLM-4.6V-Flash 中文能力强，纯中文 prompt 既稳又便于维护；中英混杂反而可能触发某些模型的中英切换抖动。英文 prompt 版本作为多语言扩展的字段位预留（`prompts.json` 结构天然支持）。

### 2. 为什么 fast 模式加 few-shot 例答

fast 要求模型一次吐出六层嵌套 schema（场景图 + 空间布局 + OCR + 上下文 + 情感 + 推理链），对中文模型的 JSON 遵从度是硬要求。光靠 schema 描述不够稳定——模型可能输出合法 JSON 但填错字段语义。给一个最小可行例答（狗叼伞雨后街景），把模型稳定在"格式正确 + 字段语义正确"两个维度上。

例答刻意覆盖了三种空值回填模式，引导模型宁缺勿造：

- `"无法判断"` —— 时间/季节无法确定时
- `"无明显文化或地理特征"` —— 无文化背景线索时
- `"无足够线索"` —— 前后事件无法推断时

### 3. 三个稳定手段叠加

1. **schema 内嵌强约束指令**。prompt 里不止贴 schema，还附：
   - observations 只填直接可见事实，推测全部放 inferences
   - 无法推断的字段填"无法判断"/"无足够线索"，不要编造
   - 第一个字符必须是 `{`，最后一个字符必须是 `}`
2. **few-shot 最小可行例答**。拼在主 prompt 前，标注"仅作格式参考，内容据实际图片填写"。
3. **解析失败显式降级**。`parse_json_response` 返回 `parse_failed: True` + raw_response，fast 结果附 `hint` 建议切 `--mode deep`，不默默吞错。

### 4. query 是事实复核通道，不是补刀

query 模板把定位写成"严谨的视觉核查员"，要求：
- 只基于图片中可见的内容回答
- 信息不足时明确说"无法从图片中确定"，不编造
- 是非题先答"是/否"再解释；计数题给确切数字；空间问题具体描述位置
- 明确区分"直接看到"和"据此推断"

这呼应 SKILL.md Phase 2 的设计：对 understand 结果中需核实的关键论断做二次求证。国产 VLM 对客观论断可能幻觉，query 是复核手段。

## 各维度提示词速览

| 字段          | 用途           | 输出形式      | 关键约束                                   |
| ------------- | -------------- | ------------- | ------------------------------------------ |
| scene_graph   | 场景图         | 严格 JSON     | 只返回 JSON，第一个字符必须是 `{`          |
| spatial       | 空间布局       | 自然语言      | 只基于可见证据，精确描述位置关系           |
| text_ocr      | 文字提取       | 纯文字        | 无文字返回空字符串，保留原始语言           |
| context       | 上下文推断     | 自然语言      | 明确区分观察和推断，无法确定时直说         |
| emotion       | 情感氛围       | 自然语言      | 说明哪些视觉线索导致结论                   |
| reasoning     | 因果推理链     | 自然语言五步  | 观察/推断/背景知识/结论/替代解读           |
| query         | VQA 事实复核   | 自然语言      | 只基于可见内容，无法确定直说               |

## 贡献指南

- **改 prompt**：编辑 `assets/prompts.json`，保持 JSON 合法（注意 `\n` 转义）。
- **加多语言**：在 `prompts.json` 顶层新增语言字段集合（如 `"en"`），`vision.py` 目前按固定键读取，多语言落地时需同步扩展加载逻辑。
- **验证**：改动后用一张测试图分别跑 `fast` 与 `deep`，确认输出 JSON 合法、字段语义正确（尤其空值回填是否符合"宁缺勿造"）。
