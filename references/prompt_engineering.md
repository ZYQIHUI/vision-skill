# 提示词工程 — Vision Skill

本文档记录 `assets/prompts.json` 的设计逻辑，供社区贡献者优化提示词时参考。
改提示词即可提 PR，不需要碰 Python 代码。

## 设计原则

### 1. 为什么 prompt 全中文

提示词是喂给视觉模型(默认 `agnes-2.5-flash`,备用 `Qwen/Qwen3.5-4B` / `GLM-4.6V-Flash`)的,语言由 VLM 决定,与上游是 GLM-5.2 还是 DeepSeek 无关——上游 LLM 读的是脚本吐出的 JSON,不是 prompt。国产 VLM 中文能力强,纯中文 prompt 既稳又便于维护;中英混杂反而可能触发某些模型的中英切换抖动。英文 prompt 版本作为多语言扩展的字段位预留(`prompts.json` 结构天然支持)。

### 2. 视觉模型做感知层,文本模型做认知层

核心分工:视觉模型只负责**轻量感知**(看 + 吐结构化 JSON),把判断、综合、信任评估交给上游文本模型。为实现这一点,fast 输出新增两个"元信息"字段:

- **`image_integrity`** —— 图片质量与完整性自检。视觉模型在分析前先判断图片是否清晰/完整/可疑。若图片模糊、损坏、被裁剪、或内容异常(如用户手误上传的残缺图),`suspicious=true` 并说明原因。这给文本模型一个明确信号:图片本身可能不靠谱,不要盲目下结论。
- **`confidence`** —— 各维度置信度 (high/medium/low)。视觉模型对看不清或不确定的部分如实标 low,文本模型据此决定该采信哪些论断、哪些需要二次复核。

**为什么这样设计**:直接让上游文本模型"看"图片做不到,它只能信视觉模型的输出。若视觉模型对自己没把握的部分也雄心勃勃地编,文本模型就会基于幻觉推理。有了 `suspicious` 和 `confidence`,文本模型能识别"图片有问题"或"此维度不可靠",从而礼貌提示用户、或转向 query 复核,而不是硬给结论。

### 3. 精简 prompt 减轻视觉模型负担

fast 模式过去要求一次吐出六层嵌套 JSON + 冗长 schema 约束,负担重、响应慢。优化方向:

1. **schema 字段值处去掉描述性注释**,只留键名 + 空字符串占位。
2. **约束指令合并压缩**,去掉重复表述(如"只返回 JSON"原来出现两次)。
3. **few-shot 例答精简**,只保留最能稳定 schema 的字段,减少重复消耗。

实测(apples 对比,单位=字符数):

| 维度 | 旧 | 新 | 变化 |
| ---- | -- | -- | ---- |
| fast_comprehensive | 1222 | 1109 | -9% |
| scene_graph | 263 | 198 | -25% |
| spatial | 104 | 60 | -42% |
| text_ocr | 63 | 53 | -16% |
| context | 181 | 86 | -52% |
| emotion | 111 | 65 | -41% |
| reasoning | 139 | 76 | -45% |
| query.template | 171 | 172 | ~0 |

费减的是 prompt 长度,增的是输出信息密度(新增 2 个判断字段)。整体上视觉模型看更少、想更多、输出更负责。

### 4. 三个稳定手段叠加

1. **schema 内嵌强约束指令**。prompt 里不止贴 schema,还附:
   - 先判断图片质量与完整性,异常时 `suspicious=true` 并说明原因
   - 逐维度标置信度,看不清/不确定填 `low`
   - 无法推断的字段填"无法判断",不编造
   - 第一个字符必须是 `{`,最后一个字符必须是 `}`
2. **few-shot 最小可行例答**。拼在主 prompt 前,标注"仅作格式参考,内容据实际图片填写"。例答刻意覆盖三种空值回填模式:无法判断 / 无明显文化或地理特征 / 无足够线索;并示范 `image_integrity` 正常时 `suspicious=false`。
3. **解析失败显式降级**。`parse_json_response` 返回 `parse_failed: True` + raw_response,fast 结果附 `hint` 建议切 `--mode deep`,不默默吞错。

### 5. query 是事实复核通道,不是补刀

query 模板把定位写成"严谨的视觉核查员",要求:
- **若图片模糊、不完整或异常,先指出图片问题,再尽力回答**(应对用户手误上传的残缺/损坏图)
- 只基于图片中可见的内容回答
- 信息不足时明确说"无法从图片确定",不编造
- 是非题先答"是/否"再解释;计数题给确切数字;空间问题具体描述位置
- 明确区分"直接看到"和"据此推断"

这呼应 SKILL.md Phase 2 的设计:对 understand 结果中需核实的关键论断做二次求证。国产 VLM 对客观论断可能幻觉,query 是复核手段。

## 各维度提示词速览

| 字段          | 用途           | 输出形式      | 关键约束                                   |
| ------------- | -------------- | ------------- | ------------------------------------------ |
| image_integrity | 图片质量/完整性自检 | JSON 对象  | suspicious 标记异常,note 说明原因         |
| confidence    | 各维度置信度     | JSON 对象     | 看不清/不确定填 low                        |
| scene_graph   | 场景图         | 严格 JSON     | 只返回 JSON,第一个字符必须是 `{`          |
| spatial       | 空间布局       | 自然语言      | 只基于可见证据,精确描述位置关系           |
| text_ocr      | 文字提取       | 纯文字        | 无文字返回空字符串,保留原始语言           |
| context       | 上下文推断     | 自然语言      | 明确区分观察和推断,无法确定时直说         |
| emotion       | 情感氛围       | 自然语言      | 说明哪些视觉线索导致结论                   |
| reasoning     | 因果推理链     | 自然语言五步  | 观察/推断/背景知识/结论/替代解读           |
| query         | VQA 事实复核   | 自然语言      | 图片异常先指出,再回答;无法确定直说        |

## 贡献指南

- **改 prompt**:编辑 `assets/prompts.json`,保持 JSON 合法(注意 `\n` 转义)。
- **加多语言**:在 `prompts.json` 顶层新增语言字段集合(如 `"en"`),`vision.py` 目前按固定键读取,多语言落地时需同步扩展加载逻辑。
- **验证**:改动后用一张正常图和一张异常图(模糊/裁剪)分别跑 `fast` 与 `deep`,确认:正常图 `suspicious=false` 且置信度合理;异常图能正确标记 `suspicious=true`.同时确认输出 JSON 合法、字段语义正确(尤其空值回填是否符合"宁缺勿造")。
